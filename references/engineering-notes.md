# Operational lessons from actual releases

- Many independent imported short MP4s crashed Premiere in the original session. A **single prepared montage source with separate timeline in/out points** was stable. Keep full-frame SELECTS and original timestamp audit for future changes. Do not describe pre-cropped media as fully reversible native crop.
- Emit XML using encoding `utf-8`, not the `utf8` alias, especially with Cyrillic paths. When reading old files an alias-only prolog can be normalized in memory; don't alter archived originals merely to fix parser compatibility.
- ExtendScript `File.flush` was unavailable. Close logs normally. `Sequence.exportFramePNG` was unavailable; QE exportFramePNG imported an unwanted image into the project. Don't use either for delivery QA.
- Native `/C es.processFile` launch worked only in a fresh Premiere process in this environment. Sending it to an already running instance did not reliably execute. Never kill a user's unsaved Premiere project. Inspect title/save state and close only an owned saved instance; otherwise use an available scripting runner or let the user complete a necessary handoff.
- Use unique native scratch project names. Existing files can trigger Save As prompts, stale projects or imports merged into an old session. Preserve earlier draft exports in a local archive before writing a new version. Verify the actual final saved project's media paths.
- Decode actual container rather than trusting `.mp3` or `.m4a`. Prepare PCM WAV for Premiere; the original session had a mislabeled compressed file causing File Import Failure.
- Analyze L/R and mono as needed. OVERDOZ left-only ASR missed its early vocals; CUPSIZE mono mixing weakened vocals. ASR words are noisy. Hear complete phrase boundaries and use timing evidence, not a false exact transcript.
- A generic landscape contact-sheet row height hid portrait gameplay. Compute the tile height from decoded frame dimensions; crop embedded gameplay only after observing real coordinates.
- Marker/white-pixel detection also fired on white character models and menus. Build detector templates from known UI regions in the normalized geometry. An unfamiliar HUD needs fresh checks. Manual first/mid/last frames found weak noncombat candidates that passed automation.
- A late replacement briefly introduced six buy-phase frames. A scanner that merely printed hits was insufficient: require inspection/resolution before export. Recheck the changed slot in exported pixels, not only the intermediate file; native cache can retain older media.
- Drive connector raw fetch had a large-file limit. Prefer connected metadata/previews. Authorized public official HTTPS download can be a fallback. Resumable HTTP ranges must verify 206, exact Content-Range and final expected size; six network threads per file/two files were useful in that session, not required for every run. Don't publish personal IDs or credentials or bypass access restrictions.
- Disk space was constrained. Preserve source handles and audit before removing any temporary full recording. Check references in **all affected saved projects**, not only the latest. Never remove original user Downloads. NTFS hardlinks can save space but require both paths to remain logically managed; normal copies are more portable.
- Sparse evidence is not complete review. Do not claim all files watched, globally fresh footage, confirmed unique kill counts or final user approval unless actually established. Historical exported counts and approvals are different evidence types.

These are practical workarounds, not permanent guarantees across Adobe versions, operating systems or HUDs. Reuse approved values first, adapt only when an observed mismatch requires it.
