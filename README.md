# Standoff TikTok Editor for Codex

Переносимый навык плотного монтажа Standoff 2: музыка → короткие боевые моменты → вертикальный MP4 + редактируемый Premiere Pro 2024. Создан по реальному циклу правок автора; утверждённый эталон — POVOD FULL. Инструкции включают все последующие уточнения по плотности, запрещённым кадрам и точечным исправлениям.

## Установка и запуск

В Codex с доступным установщиком навыков напишите:

> Установи навык https://github.com/I-am-Cheese/standoff-tiktok-editor . Навык лежит в корне; имя standoff-tiktok-editor.

Либо клонируйте репозиторий **в отдельную папку** `~/.codex/skills/standoff-tiktok-editor` (Windows: `%USERPROFILE%\.codex\skills\standoff-tiktok-editor`). Если список навыков не обновился, начните новую сессию Codex. При использовании skill-installer через командную строку задавайте корневой путь `--path . --name standoff-tiktok-editor` вместе с URL/именем этого репозитория.

Примеры:

> Используй $standoff-tiktok-editor. Делаем ролик.

Навык спросит музыку и предпочтения по исходникам, если они отсутствуют.

> Используй $standoff-tiktok-editor. Музыка: путь к файлу. Исходник выбирай сам из моей папки.

При первом использовании другим человеком нужны **его** доступные записи/папка, путь для релизов и при необходимости своя графика. Личный Google Диск автора не является общей библиотекой. По умолчанию сохранены семь исходных ступеней Exit и геометрия Chad; графика лежит в assets и может заменяться через локальный профиль.

## Что внутри

- `SKILL.md`: короткий рабочий регламент, обязательные вопросы, экономное делегирование.
- `references/editing-rules.md`: окончательные требования и точные значения.
- `references/decision-history.md`: ошибки, откаты и уточнения пользователя.
- `references/historical-context.md`: обезличенный сохранённый рабочий контекст с отметкой исторических решений; читать только при необходимости.
- `references/workflow.md`, `music.md`, `premiere.md`, `state-schema.md`: практическая сборка и проверки.
- `scripts/`: переносимые инструменты анализа, рендера, создания XML/JSX и проверки нативного проекта.
- `assets/`: оригинальные PNG, семь ступеней логотипа, готовый прозрачный Chad overlay и проверенный экспортный пресет.
- `examples/history-ledger.json`: обезличенный журнал всех сохранённых релизов и исправлений.
- `examples/frame-map.jsonl`: соответствие каждого выходного кадра интро/геймплея исходному моменту для записанных релизов. Это карта таймингов, не изображения кадров.

Инструкция не загружает весь архив каждый раз. Для обычного ролика нужны только актуальные правила, локальное состояние и текущий job. История и покадровые карты доступны по необходимости. Пакет не содержит музыку, видеозаписи, личную переписку, закрытые рассуждения, пароли или личные ссылки на Drive. Сохраняются наблюдаемые решения и проверяемые результаты. Подробный локальный архив исходного рабочего процесса хранится отдельно у автора.

## Сабагенты и расход

Один свежий рабочий агент на ролик; второй только для полезной параллельной задачи. Максимум два одновременно, без рекурсии и копирования всей переписки. Один процесс владеет Premiere и изменениями релиза. Рабочие возвращают компактные JSON и краткий отчёт. Это уменьшает объём служебных данных в главном чате; общий расход токенов может увеличиваться, фиксированный процент лимита Plus не обещается.

## Зависимости и ограничения

Python 3.9+, FFmpeg и установленный Premiere Pro 2024 для настоящего `.prproj` и штатного экспорта. NumPy нужен только анализатору транзиентов, Pillow — только контактным листам; остальные инструменты используют стандартную библиотеку Python. Распознавание вокала необязательно и применяется к коротким участкам при необходимости. Доступность инструментов сабагентов/управления Premiere зависит от окружения Codex.

XML — промежуточный формат. Native проект создаёт сам Premiere после запуска подготовленного JSX. Скрипты сами Adobe не запускают, не скачивают записи и не публикуют видео. Анализатор не умеет гарантированно определять убийства, припевы или модность музыкального отрезка: агент проверяет контекст и кадры. Результат будущего творческого выбора не гарантирован на 100%; воспроизводятся конкретные правила и механика.

## Проверки пакета

Проверка синтаксиса Python, структуры навыка, сборка синтетического рендера с кириллицей/апострофом в путях, создание трёх вложенных XML-секвенций, защита от перезаписи, проверки ошибок тайминга и повторов. Нативный валидатор дополнительно проверен на существующем реальном проекте Premiere: 75 склеек, три секвенции, MAIN в корне, 21 подключённый материал и общая GAMEPLAY для фона и переднего плана. Эти проверки не заменяют просмотр каждого нового ролика.

Повторить короткую интеграционную проверку: `python scripts/smoke_test.py --ffmpeg путь-к-ffmpeg`. Она создаёт временное синтетическое видео, не запускает Adobe и не читает личные исходники. Проверка инструкции на четырёх сценариях подтвердила вопросы при отсутствии данных, запрет подмены недоступной музыки, сохранение длительностей при точечных исправлениях и отделение профиля другого пользователя.

Оригинальные скрипты и документация распространяются по MIT. У существующей графики и данных Adobe сохраняются соответствующие права; для чужого канала предпочтительна собственная графика.
